# 手机端与微信小程序开发需求

> 需求整理日期：2026-11-08。
> 本文是待开发的产品方案。当前仓库只有网页交互原型和早期后端演示，尚未实现微信小程序、真实地图定位或分享海报。

## 产品目标

让拾得人用尽量少的操作留下有效线索，让失主能方便地查找、核实和认领。

**不能让有爱心的人花太多时间在提交这件事上。**

以“简单物品争取约 30 秒完成发布”为设计目标；这不是已验证的性能承诺。通过真实试用观察完成时间、放弃原因和误填情况，再调整流程。

## 第一版的发布流程

打开小程序 → 选择物品类别 → 拍照或简短描述 → 确认拾得地点与时间 → 预览并发布。

- 不在首页要求登录；在确实需要保存或提交时再引导必要的登录步骤。
- 首屏提供“我捡到了”和“我丢东西了”两个明确入口。
- 物品类别可点选；拾得时间默认今天，允许修改，不能选择未来时间。
- 图片和描述至少提供一种有效线索，不强制同时填写；证件类不要求拍照，也不录入真实身份信息。
- 不强制填写手机号、微信号、完整姓名、门牌地址或物品长篇说明。
- 发布前展示简洁的确认卡，允许修改时间、地点及公开内容。
- 网络失败时保留当前编辑内容并支持重试；防止重复点击造成重复记录。草稿需支持清除并设置保留期限，不长期留存敏感原图。

## 需求一：微信小程序

### 用户可以做什么

- 在微信内查找、发布和查看物品，不需要额外安装独立 App。
- 在手机上查看图片、筛选片区、提交认领申请和查看自己的记录。
- 分享物品线索，接收由用户主动订阅的必要进展通知；通知能力以后续开通情况为准。

### 建议页面

| 页面 | 主要内容 |
| --- | --- |
| 首页／寻物广场 | 搜索、片区与类别筛选、物品卡片、发布入口 |
| 发布拾得物 | 类别、图片或描述、地图选址、时间、发布预览 |
| 物品详情 | 公开线索、大致地点、最新状态、认领和分享入口 |
| 认领申请 | 私密特征输入、核验说明、申请进展 |
| 我的记录 | 自己发布的物品、自己的申请、授权的状态操作 |
| 分享海报 | 海报预览、保存图片、分享指引 |

### 开发边界

当前 HTML 页面可作为设计与交互参考，不能直接视为已完成的小程序。正式版本需要微信端页面、共享后台、数据库、文件存储和账号权限管理。网页端与小程序端应尽可能复用同一套服务和状态规则。

发布前需要完成小程序账号及适用类目配置、必要接口权限申请、隐私声明配置、服务部署和平台审核。具体要求以届时微信官方规则及审核结果为准。

## 需求二：定位与地图选址

### 拾得人的操作

1. 点击“选择拾得地点”，主动使用定位或地图选点。
2. 授权后，以当前位置为选址起点，展示附近地标供选择。
3. 显示提醒：“这是当前所在位置，请确认是否为拾得地点。”
4. 可拖动地图、搜索地标或切换城市，确认后自动带入可读的地点名称。
5. 发布预览明确显示其他人将看到的地点范围。

当前位置不一定是拾得位置，不能把定位结果直接自动发布。用户可能捡到物品后已经回家，也可能是在另一个城市拾得。

### 无法定位时

- 拒绝定位、手机定位关闭、网络超时或定位不准，都能继续手动选城市／片区或填写公共地标。
- 不反复弹窗要求授权，不以开放定位为发布的唯一条件。
- 地图服务故障不应阻塞基本的文字地点发布流程。

### 公开范围与数据处理

- 默认公开“大致片区／公共地标”，不公开住宅门牌或个人实时精确位置。
- 地图预览应区分“精确选点”和“最终公开范围”；不能只模糊显示文字，却在公开接口中返回精确经纬度。
- 尽可能在设备端把精确定位转为粗粒度片区或公共地标，只上传业务必需的信息；不需要的精确坐标不保存、不写入日志。
- 使用地理编码等第三方地图服务前，应确认实际传输的信息和服务配置，并在隐私说明中如实告知。
- 拍照上传需去除 EXIF 等定位元数据，防止通过照片绕过地点隐私保护。
- 附近搜索是后续能力：使用粗粒度位置筛选候选，不持续追踪用户位置。

### 完成标准

- 可以通过地图选择地点，系统自动填入地点名称。
- 可以修改定位结果，不会将当前位置直接当作拾得地点发布。
- 拒绝定位后仍能完成手动选址和发布。
- 公开详情、分享海报及公开接口不泄露不应公开的精确位置。

## 需求三：分享海报与微信传播

### 分享入口

在物品详情和发布成功页提供“生成分享海报”。先预览，再由用户决定是否保存和分享，不自动发送给任何人。

### 海报包含什么

- “失物招领”或“寻物线索”等明确标题。
- 已完成脱敏的物品图片，或默认的类别插画。
- 物品类型、外观简述、日期、大致拾得片区。
- 生成时的物品状态及海报生成日期。
- 指向该条物品详情的小程序码及“扫码查看最新状态”的说明。
- 项目标识和简短公益说明。

不放入完整姓名、证件号码、手机号、私密认领特征、原始证件照片或住宅精确位置。证件类优先使用通用插画，其他照片也要在生成海报前复核。

### 从生成到分享

选择分享 → 预览脱敏海报 → 保存图片 → 用户自行分享到朋友圈或聊天。

支持范围内可另接入微信原生的好友分享、朋友圈分享能力，并遵守相应限制。海报生成不等同于自动发布朋友圈；不强制分享，不用积分或认领资格诱导分享。

小程序码必须指向真实、可访问的物品详情。尚未发布小程序时，原型应明确使用“演示占位”，不能伪造可用的小程序入口。

### 状态变化与过期传播

- 海报图片转发后无法远程修改，物品归还后旧图片仍可能流传。
- 扫码详情必须查询最新状态；已归还则关闭认领入口，删除或下架则展示适当提示。
- 重新生成海报时使用最新状态，不继续生成标注“待认领”的旧版本。
- 临时海报和图片需有清理机制，不能无限期保留个人信息。

### 完成标准

- 生成的图片在手机上清晰可读，关键信息和二维码不被裁切。
- 用户可在保存前检查公开内容；拒绝相册权限时仍能返回查看海报。
- 扫码能打开对应详情，并显示最新状态。
- 在不同常见屏幕尺寸下验证生成、预览和保存流程。

## 开发顺序

| 阶段 | 交付内容 | 如何判断可进入下一步 |
| --- | --- | --- |
| 1. 完善网页原型 | 简化发布表单、地图选址交互稿、海报样式预览 | 发起人可实际点选，并明确哪些数据公开 |
| 2. 实现小程序最小版本 | 微信登录、登记与检索、真实地图选址、后台存储、认领核验和基本管理 | 在测试环境走通发布到归还流程，权限和隐私保护通过检查 |
| 3. 完善传播与运营 | 真实小程序码、海报生成保存、适用的微信分享、投诉与数据清理 | 真机验证分享与扫码后的最新状态一致 |

阶段 2 之前应明确谁负责核验、如何处理冒领及谁有权修改状态。提交申请不能直接判定认领成功；只有获得相应权限的人才能操作记录。

积分、勋章、悬赏、智能推荐和复杂地图聚合暂列为后续候选，优先保障发布省事、找物方便、核验可靠。
